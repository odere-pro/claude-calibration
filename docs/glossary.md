# Glossary

The vocabulary these docs use, aligned with Claude Code's own terminology. Each term is cited to
the official doc that uses it. Use these words verbatim across the doc set.

| Term                               | Meaning                                                                                                                                                                                                                                                                                                                                                                | Source                                                                                                                                                                          |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Feature** / **extension**        | A unit of Claude Code you add or configure: **CLAUDE.md**, **`.claude/rules/`**, **Skills**, **Subagents**, **MCP**, **Hooks**, **Plugins** — plus **Settings** (the config substrate) and **Agent teams** (experimental). The things you add on top of the built-in tools are the _extension layer_.                                                                  | [Extend Claude Code](https://code.claude.com/docs/en/features-overview)                                                                                                         |
| **Scope** (a.k.a. **level**)       | Where a feature is defined and who it applies to. The scopes: **managed** (a.k.a. _enterprise_ / _policy_ — admin-deployed, can't be overridden), **user** (a.k.a. _personal_ — `~/.claude/`), **project** (`.claude/` in the repo, committed), **local** (`.claude/settings.local.json`, `CLAUDE.local.md` — git-ignored), **plugin** (shipped by an enabled plugin). | [Settings](https://code.claude.com/docs/en/settings), [Skills](https://code.claude.com/docs/en/skills), [Extend Claude Code](https://code.claude.com/docs/en/features-overview) |
| **Layering**                       | How the same feature defined at several scopes combines: **additive** (CLAUDE.md, hooks — all contribute) vs **override-by-name** (skills, subagents, MCP — one definition wins by priority).                                                                                                                                                                          | [Extend Claude Code → how features layer](https://code.claude.com/docs/en/features-overview)                                                                                    |
| **Precedence**                     | For override-by-name features and for settings, the priority order that decides which scope wins on a clash.                                                                                                                                                                                                                                                           | [Settings](https://code.claude.com/docs/en/settings)                                                                                                                            |
| **CLAUDE.md**                      | The always-on instruction files Claude loads every session: `CLAUDE.md`, `CLAUDE.local.md`, and `.claude/rules/*.md`. Delivered as a user message after the system prompt — context, not enforced configuration.                                                                                                                                                       | [Memory](https://code.claude.com/docs/en/memory)                                                                                                                                |
| **Auto memory**                    | Notes Claude writes itself across sessions, under `~/.claude/projects/<project>/memory/` (`MEMORY.md` index + topic files). Distinct from CLAUDE.md (which you write).                                                                                                                                                                                                 | [Memory → auto memory](https://code.claude.com/docs/en/memory)                                                                                                                  |
| **`.claude/rules/`** (rules)       | Topic- or path-scoped instruction files. Load like `.claude/CLAUDE.md`; with `paths:` frontmatter they load only when Claude works with matching files.                                                                                                                                                                                                                | [Memory → rules](https://code.claude.com/docs/en/memory)                                                                                                                        |
| **Importing `AGENTS.md`**          | Claude Code reads `CLAUDE.md`, **not** `AGENTS.md`. To use the open-standard file: `@AGENTS.md` inside `CLAUDE.md`, or `ln -s AGENTS.md CLAUDE.md`.                                                                                                                                                                                                                    | [Memory → AGENTS.md](https://code.claude.com/docs/en/memory)                                                                                                                    |
| **YAML frontmatter**               | The `---`…`---` config block at the top of a subagent or skill file.                                                                                                                                                                                                                                                                                                   | [Subagents](https://code.claude.com/docs/en/sub-agents), [Skills](https://code.claude.com/docs/en/skills)                                                                       |
| **Built-in command**               | A slash command the CLI handles directly (`/doctor`, `/config`, `/memory`, …); marked **Command** in the commands reference.                                                                                                                                                                                                                                           | [Commands](https://code.claude.com/docs/en/commands)                                                                                                                            |
| **Bundled skill**                  | A skill that ships with Claude Code (`/simplify`, `/debug`, `/batch`, `/loop`, `/fewer-permission-prompts`, `/claude-api`); marked **Skill** in the commands reference.                                                                                                                                                                                                | [Commands](https://code.claude.com/docs/en/commands), [Skills → bundled skills](https://code.claude.com/docs/en/skills)                                                         |
| **Plugin** / **marketplace**       | A plugin bundles skills, subagents, hooks, MCP/LSP servers, monitors, and a `settings.json` into one installable unit (manifest at `.claude-plugin/plugin.json`). A marketplace is a hosted collection of plugins. Plugin skills are namespaced `plugin-name:skill-name`.                                                                                              | [Plugins](https://code.claude.com/docs/en/plugins), [Marketplaces](https://code.claude.com/docs/en/plugin-marketplaces)                                                         |
| **Context cost**                   | How much of the context window a feature consumes and when it loads — CLAUDE.md: full, every request; skills: descriptions every request, body on use; MCP: tool names at start, schemas on use; hooks: zero unless they return output; subagents: isolated window.                                                                                                    | [Extend Claude Code → context costs](https://code.claude.com/docs/en/features-overview)                                                                                         |
| **Configure / Validate / Improve** | The three sections every feature doc in this set applies. A doc-set convention, not an official Claude Code term.                                                                                                                                                                                                                                                      | —                                                                                                                                                                               |
